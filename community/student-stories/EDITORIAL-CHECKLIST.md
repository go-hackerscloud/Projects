# Maintainer Story Review Checklist

Use this list **privately** to review each potential publication. Do not add names, consent forms, contact details or identity-verification documents to the public repo.

| Checkpoint | Question | Status |
| --- | --- | --- |
| Authenticity | Is the story original, accurately attributed and voluntarily submitted? | Pending |
| Scope | Are lab, project and GHC product references accurate? | Pending |
| Outcomes | Are certification, employment, numbers and causal claims supportable? | Pending |
| Consent | Did the subject approve the exact public wording and displayed links? | Pending |
| Photos | Is every identifiable image separately cleared? | Pending |
| Privacy | Is sensitive and unnecessary identifying data omitted? | Pending |
| Marketing | Are reuse permissions for GitHub vs advertising separately documented? | Pending |
| Editorial review | Did a second maintainer approve publication? | Pending |
| Correction | Does the published page link to a correction/withdrawal route? | Pending |

## Possible decisions

**Approve:** all checks pass, wording is consented, publication has a named owner internally.

**Request changes:** problems are fixable without publishing sensitive data.

**Decline / keep private:** consent absent, unverifiable outcomes, personal risk, or incompatible content permissions.

## Publication output

Publish only the approved story and permitted public links. Keep private consent evidence separate, subject to a reviewed retention and access policy.
