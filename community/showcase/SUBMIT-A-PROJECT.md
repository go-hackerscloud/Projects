# Submit Your Project to GHC Community Showcase

**Audience:** learners, alumni, mentors and community members with an original learning artifact.

**You can apply even if you have not completed a certification or a paid GHC course.** The showcase recognizes educational projects, not a purchased product or employment outcome.

## What to prepare

- **Project URL:** a public project you own and have permission to share.
- **Title and audience:** what a beginner or practitioner will learn.
- **Learning objective:** the one problem you solved or examined.
- **Scope:** local-only, synthetic, or clearly authorized.
- **Reproducibility:** prerequisites, commands where safe, expected observations and limits.
- **Evidence:** sanitized results; no session secrets, customer data, paid answers or unauthorized target details.
- **Professional reflection:** what was demonstrated versus inferred, how you would improve or retest it.
- **Accessibility:** if possible, note a low-cost or browser-friendly approach.

## Simple submission path

1. Read the [Student Portfolio Toolkit](../../student-portfolio/README.md) and prepare a project README.
2. Run the [publication checklist](./REVIEW-CHECKLIST.md).
3. Use the **Community Project Proposal** form in [GitHub Issues](https://github.com/go-hackerscloud/learn-with-ghc/issues/new/choose).
4. Describe only **already-public, non-sensitive** work in the issue. A link and short project description are sufficient for the first review.
5. Respond to review feedback in the issue. Once approved, propose a Markdown showcase entry in a pull request—or ask the maintainer to prepare one after publication authorization.
6. Ensure the final entry accurately identifies the evidence, limitations and permitted public attribution.

## Not suitable for a public issue

Do not share: phone numbers, emails, student IDs, identity documents, personally identifying testimonial information, private consent forms, certificates containing personal data, customer screenshots, login sessions, access keys, exploit results from unapproved systems, or proprietary paid lessons/exam questions.

If a submission requires verifying an identifiable career or certification outcome, ask for a **private** submission route through the [official contact page](https://gohackerscloud.com/contact-gohackerscloud). A public GitHub issue is not the place to perform private verification.

## How selection works

A maintainer checks: **originality, permission, technical clarity, evidence, publication safety, reproducibility and learner value**. See the [review checklist](./REVIEW-CHECKLIST.md). A selected showcase entry is not an official certification.

## After acceptance

Students may choose public credit via an already-public GitHub username; pseudonymous attribution is also acceptable. A maintainer will confirm the exact link and display attribution for the showcase. Any separate quotation, image, social-media reuse or personal story requires distinct permission.
