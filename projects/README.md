## Proposed reusable project format

Each new published project should contain:

1. **Objective and learning outcomes** — what the student will be able to demonstrate.
2. **Prerequisites** — required foundation knowledge and tools.
3. **Architecture** — an annotated diagram or simple explanation.
4. **Authorized environment** — isolated demo, synthetic data, or a system you own.
5. **Guided steps** — commands with purpose, expected observations and troubleshooting.
6. **Evidence** — safe screenshots, sanitized outputs and a short report.
7. **Assessment** — questions or clear completion criteria.
8. **Cleanup** — how to remove resources and avoid unnecessary cloud charges.

Projects will be linked from the Academy and Foundation overview pages when their material is actually published and reviewed. There is no promise of unrestricted access to the separate paid GHC Labs runtime.

## First published project

**[Foundation Project 01 — Linux Security Fundamentals](./foundation-projects/linux-security-fundamentals/README.md)** is a reproducible beginner exercise using a local Linux terminal, synthetic files, and an evidence report. No premium laptop, cloud account or full Kali VM is required.

Other project ideas remain planned. Learners can use the [report template](./foundation-projects/linux-security-fundamentals/REPORT-TEMPLATE.md) and explore [industry practice](../industry-practice/README.md) to connect training observations to professional assessments.


## Another available beginner project

**[Foundation Project 02 — HTTP Response Explorer](./foundation-projects/http-response-explorer/README.md)** uses a local Python server and `curl` to explain HTTP 200/404 responses and headers. It does not require a premium laptop or GHC membership.
