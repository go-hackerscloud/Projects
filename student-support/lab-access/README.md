# GHC Labs — Access, Setup and Troubleshooting

**Pain point:** configuring Kali, a vulnerable target, multiple networks and a local hypervisor can consume more time than the lesson itself.

GHC Labs aims to offer **preconfigured browser-accessible practice environments** so eligible learners can spend more time on the objective and less time maintaining a local stack.

[Public GHC Labs overview](https://gohackerscloud.com/hands-on-cybersecurity-labs)

## Before you launch

1. Review the lesson objective and permitted target scope.
2. Confirm you are enrolled and signed in if the lesson requires it.
3. Open the official Academy lesson; use its **Start Lab** action rather than guessing runtime URLs.
4. Allow the lab to prepare; follow the page's instructions.
5. Use the terminal or desktop interface provided for your environment.
6. Record sanitized findings and end the lab using the provided control.

Exact buttons and available features can vary by lesson, browser and account.

## What browser-hosted labs may reduce

- Local VM installation and hypervisor conflicts
- Maintaining a Kali image and compatible target versions
- Local virtual-network setup
- Rebuilding a practice environment for every exercise

They **do not replace** network access, enrollment where required, time-limited sessions or responsible handling of evidence.

## Common problems and what to check

| Symptom | Learner action |
| --- | --- |
| Sent to sign-in | Complete the official login flow and verify access |
| Preparing page seems stuck | Check internet; refresh only if instructions permit, then report the lab ID and approximate time |
| Terminal doesn't respond | Check the browser tab, connection and session status; avoid repeated launch attempts |
| Desktop doesn't display | Try a supported updated browser and confirm the lesson offers desktop mode |
| Session expired | Save permitted notes, return through the Academy and launch again if eligible |
| Unsure what to type | Re-read the prerequisite concepts and use the lesson's command blocks |

Never post passwords, session cookies, authentication tokens or private lab endpoints in public issues. Contact support via [official contact](https://gohackerscloud.com/contact-gohackerscloud).

## How to capture evidence

Record the lab title, task, command purpose, expected versus actual result, explanation, and remediation idea. Do not copy private solution keys, credentials or proprietary paid guides into public repositories.
